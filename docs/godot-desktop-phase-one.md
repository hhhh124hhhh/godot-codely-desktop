# Godot 桌面第一阶段实现记录

关联 [Issue #20](https://github.com/hhhh124hhhh/godot-codely-desktop/issues/20)。本轮先落地项目概览、原生开发会话与编辑器基础控制，完整产品方向仍见 [整体设计](godot-desktop-design.md)。

## 当前实现

- `dsh-godot-stack` 新增可选 Web 客户端入口，通过现有工作台服务注册 Godot 开发页面；保留宿主侧栏与原生聊天、模型选择、审批和取消操作。
- 使用宿主 `--dsw-alias-*` 语义色与深浅主题，统一 12/14/16/28 字阶、4/8 间距和 8px 圆角。概览与会话共用原生会话挂载点，切换概览不清空输入草稿。
- 从已注册工作区根目录识别 `project.godot`，读取真实项目名称、启动场景；普通文件夹显示纠正提示。通过原生目录选择器添加项目，已有工作区可直接切换。
- 新建会话通过 Harness 明确选择 `godot-codely-lite`，再使用插件作用域的 `ensureSession` 绑定工作台；原生会话列表与持久化仍是唯一事实来源。
- 编辑器检查连接、运行主场景、停止、刷新资源复用现有 `EditorControl`。执行对象由后端工作区解析；前端不能用请求体切换任意路径。
- 编辑器未连接、忙、超时、未保存、请求失败均有中文和英文提示。连接显示为“上次检查已连接”，不把历史成功当成实时心跳。超时不自动重试。切换项目或退出工作台会取消等待，旧响应不绑定新项目。

## 加载与进程边界

改动涉及客户端发现和激活阶段：`package.json` 声明 `dsh.client` 与 `./client`，声明工作台、locale、workspace 客户端依赖；现有 `scripts/build-godot-runtime.mjs` 从维护源码生成插件包，安装包从该生成目录读取。没有改动 bootstrap 顺序或插件解析 fallback。

后端在桌面配置 `bridge: true` 时，动态等待 `connection` 与 `workspaceRegistry`，注册 `/api/godot-desktop/{project,session,editor}`。路径基准为当前 Harness 的工作区注册记录；会话由已有 Typert 适配器创建，原生动作由已有编辑器桥转发。浏览器只请求自身已认证的 Harness 地址，不跨端口访问桥接服务。Connection 使用合成 Request URL，来源检查以实际 Host 与浏览器 Origin 对应，不放宽 CORS。

CLI 不加载 Web 客户端；Safe Mode 不加载普通 Godot 插件。插件销毁会释放注册、样式和订阅，桥接停机沿用原有生命周期。源代码、生成插件、实际 UI 挂载和正式安装版本是不同状态。

## 使用入口

重建并启动开发桌面后，在“工作台 → 已安装”中启用 **Godot 开发**，再从工作台切换菜单打开。现有用户的工作台设置保留，不强制开启或替换默认导航。打开项目文件夹后，点击“开始开发”。要使用编辑器操作，需在 Godot 项目中启用随包提供的 Godot Codely 插件并连接桥接服务。

下一批优先补齐引擎路径设置、打开 Godot 与独立运行/停止及日志。结构化差异、验证摘要和资源中心仍按后续阶段推进。

## 品牌背景与文案调整

用户指出原生配色与欢迎文案仍过于接近 DeepSeek，进一步调整如下：

- 品牌颜色权威输入为 `build/brand-theme.css`，通过现有 `brand:prepare` 的 `install-brand-assets.mjs` 注入实际 Harness HTML。浅色采用蓝灰工作区、白色面板、品牌蓝主按钮；深色采用海军蓝工作区、较亮的内容面板与蓝色操作。沿用已有语义 alias 和原生 theme 属性，不让业务插件维护独立主题。旧品牌脚本此前未接入构建且深色属性错误；现在幂等更新注入，并移除旧脚本对文档语言的强制设置。
- 原生会话从“探索未至之境 / 预览版”调整为“从一个玩法，开始创作 / Godot 游戏开发”，输入提示围绕玩法、报错、脚本、场景和验证结果。概览提示同步改为“读懂这个项目 / 做出一个玩法 / 修好一个问题”，不再向用户解释组件或宿主实现细节。
- `@deepseek-ai/dsh-client-ui-conversation@0.2.0-rc.2` 没有标题/输入提示定制 API，现有补丁增加可选 `conversation.presentation` locale namespace 与两处组件翻译适配注入，并同步 `.d.ts`。只允许六项展示文案被替换；缺少宿主词典时回退原生文案，错误、审批、离线、排队等状态继续沿用原生逻辑。文案本身保存在自有 `dsh-desktop-client-ui` 插件，通过 locale 生命周期注册与销毁。
- 不改变既有 slot 名称、顺序、挂载数量或 Composer 状态逻辑。上游提供等价 presentation API 后，可移除本补丁接缝并迁移自有词典。
- 工作台按钮、标题和段落样式限定在自有工具栏、概览、信息栏与提示区域，避免覆盖原生聊天输入控件和 Markdown 消息排版。
- 品牌/文案专项 6 套件 13 项通过；补丁在临时目录完成逆向、正向重放并按统一换行核对内容。品牌调整时未重新安装依赖；本批提交前已补跑全新 `npm ci` 与 postinstall，结果见上方批次记录。主题正文、次级文字和按钮的静态配色对比度均超过 4.5:1。
- 实际认证 HTML 携带品牌样式，真实合包携带词典与适配代码；原生会话已显示新标题和玩法输入提示，英文切换即时更新。浅色、深色和项目概览已截图检查，当前测试页面未出现 console error。静态颜色对比度：浅色正文 12.45、次级文字 6.11、按钮 6.01；深色分别 14.52、7.88、4.95。旧端口热替换开发脚本期间曾出现 conversation 服务错误，重启进入新的合包 revision 后未复现；没有把旧端口的日志当作新页面结果。
