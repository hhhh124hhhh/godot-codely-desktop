# 首批种子用户准备与验收

首批目标是少量 Windows x64、Godot 4 / GDScript 用户完成一次小项目闭环。Linux 在对应修复合入并完成该发布版本原生检查后再邀请；macOS 以实际产物和原生证据为准。

## 邀请前的放行条件

| 项目 | 要求 | 当前证据 |
| --- | --- | --- |
| 品牌与安装入口 | 主分支统一图标，下载指向本 fork | 品牌 PR #18 已合并；旧 v0.1.0-unsigned 不含新图标 |
| Windows 原生 CI | 当前待发 commit 的测试、类型、打包通过 | PR #18 Windows CI 通过；后续新增验收需重新运行 |
| 实际安装与升级 | 安装器首次安装、锁定升级回滚、覆盖升级保留 Profile、异目录安装 | 本次新增 CI 门禁，结果待执行；不得用 unpacked 启动替代 |
| 安装后客户端与预设 | bootstrap、导航与输入界面实际挂载，四个预设可用，生产 API 创建 Lite 会话，没有恢复页 | 本次新增 CDP / Typert 检查及截图，结果待执行 |
| Godot 首次任务 | 已安装应用 + 真实模型 + 小项目，文件修改、校验、运行结果正确 | 尚待真实模型人工验收，固定模型回归不能替代 |
| 发布 | 新版本下载、SHA256、已知限制和回退入口 | 现有公开版本 v0.1.0-unsigned；新版本尚未发布 |
| 用户指引与反馈 | 能找到安装、第一项任务、脱敏反馈路径 | [用户指南](seed-user-guide.md) |

CI 的安装测试只在一次性 GitHub-hosted Windows runner 上执行，会修改该测试机的快捷方式和安装注册；禁止在开发者本机直接执行。未签名模式只跳过签名断言，仍执行安装、Office 资源、启动、客户端与升级检查；签名模式继续强制验证安装器及所有 PE 的签名。

## 首批执行

先邀请 3–5 位愿意提供复现步骤的用户。每人只做一个能观察结果的小任务；按安装启动、模型配置、项目识别、工具执行、结果正确性记录首次阻塞点。修复阻断后，再请原用户使用新版本按同一步骤复测。

维护一个已脱敏的 Issue 列表，记录版本、系统、最短复现、影响和修复版本。邀请文案见用户指南；没有本 fork 群入口前不把上游社区二维码当作本项目种子群。

新版本必须新建版本号，不能覆盖已发布 tag。未签名早期包继续明确标记 unsigned；不承诺尚未验收的平台和功能。发布后复核 Releases 中的文件及哈希，再把该版本固定为首批用户下载入口。
