# Godot Codely 面板状态与文案方案

- **版本**：v1（2026-10-12）
- **性质**：方案稿。只定义面板的状态机、用户可见文案与保留数据；**不改 panel.gd / plugin.gd / bridge**，由 Codex 依据本方案落实面板协议。
- **状态源**：面板 MCP 连接生命周期（connecting / ready / lost）+ agent 对话与工具调用生命周期（执行 / 审批 / 取消）。

## 状态总览

| # | 状态 | 触发 | 是否阻塞输入 | 保留数据 |
|---|---|---|---|---|
| 1 | `connecting` 连接中 | 面板加载发起 MCP 握手，或断线自动重连 | 可输入（提交排队） | 草稿输入、场景上下文 |
| 2 | `harness-not-ready` Harness 未启动 | MCP server 未构建/未运行、端口被占、工程未导入 | 输入禁用 | 草稿输入、场景上下文 |
| 3 | `auth-failed` 认证失效 | 模型 401/402/400，或 MCP key 缺失 | 可输入（提交前提示） | 全部 |
| 4 | `tool-running` 工具执行 | agent 决策后调用 MCP 工具，等待结果回喂 | 可继续对话 | 全部（工具结果并入会话） |
| 5 | `awaiting-approval` 等待审批 | 审批策略 ask 档触发（写外部/敏感操作） | 可批准/拒绝 | 全部（审批前任务挂起） |
| 6 | `cancelling` 取消中 | 用户取消当前任务 | 输入禁用（取消完成前） | 草稿输入；已完成工具结果 |
| 7 | `disconnected-recoverable` 断线可恢复 | MCP 连接中断但会话可恢复 | 输入禁用 | 全部 + 恢复点 |
| 8 | `failed` 失败 | 不可恢复错误/协议损坏/超时 | 可重试/重置 | 草稿输入、错误日志 |

## 逐状态定义

### 1. connecting（连接中）

- **触发条件**：面板启动后 MCP client 执行 `initialize`；或从 `disconnected-recoverable` 自动重连。
- **用户可见文案**：
  - 初始：`正在连接 Godot 工程服务…`
  - 超过 5s：`连接较慢，确认 godot-mcp-server 已启动`
  - 按钮：`重试`
- **用户动作**：可编辑输入草稿（提交排队，握手成功后自动发出）；可查看连接诊断。
- **保留数据**：草稿输入、面板当前场景/工程上下文。
- **流转**：成功 → `idle`；检测到 server 缺失 → `harness-not-ready`；重连失败到上限 → `failed`。

### 2. harness-not-ready（Harness 未启动）

- **触发条件**：MCP server 未构建（`build/index.js` 缺失）、进程未运行、端口被占、或工程 `project.godot` 未导入。
- **用户可见文案**：
  - 主文案：`Godot 工程服务未就绪`
  - 副文案：`请确认 godot-mcp-server 已构建并启动（见 README「启动/常见问题」）`
  - 按钮：`重试` / `查看指引`
- **用户动作**：输入禁用；可重试，或打开 README 排查段。
- **保留数据**：草稿输入、场景上下文（就绪后继续）。
- **流转**：server 就绪 → `connecting` → `idle`。

### 3. auth-failed（认证失效）

- **触发条件**：模型接口返回 401（密钥失效）/ 402（余额不足或套餐无该接口）/ 400（网关不透传 images/audio 等）；或 `VOLC_ARK_API_KEY` / `GODOT_CODELY_TTS_API_KEY` 缺失。
- **用户可见文案**：
  - 主文案：`服务认证失败（<错误码>）`
  - 副文案（按错误码）：401 `密钥失效，请更新 API key`；402 `余额不足或无对应订阅`；400 `当前套餐不支持该接口`
  - 按钮：`打开模型设置` / `重试`
- **用户动作**：可输入（提交时给出认证提示）；打开模型/凭据设置页。
- **保留数据**：全部（不因认证失败清空会话）。
- **流转**：凭据修复 → 重试成功 → `idle`。

### 4. tool-running（工具执行）

- **触发条件**：agent 决策后调用 `mcp__godot__*` 工具，正在等待结果回喂（含 LSP 诊断、场景改写等）。
- **用户可见文案**：
  - 主文案：`正在执行：<工具名>（<简述>）`
  - 长任务（>5s）：显示进度或最近一次操作。
- **用户动作**：可继续对话；工具结果自动并入会话上下文；可查看最近工具结果。
- **保留数据**：全部（工具结果、诊断、文件改动）。
- **流转**：成功 → `idle`；单项工具失败 → 可继续其他任务，或转 `failed`（连续失败）。

### 5. awaiting-approval（等待审批）

- **触发条件**：审批策略 `ask` 档（workspace-write / read-only）下，agent 请求写工作区外、敏感或高风险操作。
- **用户可见文案**：
  - 主文案：`等待你的审批：<操作描述>`
  - 按钮：`批准` / `拒绝` / `详情`
- **用户动作**：批准 / 拒绝 / 查看详情。headless 无审批通道时 fail-closed（安全兜底）。
- **保留数据**：全部（审批决定前任务挂起，不丢弃上下文）。
- **流转**：批准 → 继续执行；拒绝 → `idle`（保留已生成内容）。

### 6. cancelling（取消中）

- **触发条件**：用户点击取消当前任务（含等待审批/工具执行/长对话）。
- **用户可见文案**：`正在取消…`
- **用户动作**：无（等待取消完成）；完成后可重新发起任务。
- **保留数据**：草稿输入；已完成的工具结果保留；未完成操作回滚到最近一致点。
- **流转**：取消完成 → `idle`。

### 7. disconnected-recoverable（断线可恢复）

- **触发条件**：MCP 连接中断（Harness 重启、端口变化、server 进程退出），但会话状态可恢复。
- **用户可见文案**：`连接中断，正在恢复…`；超过 10s 未恢复：`恢复失败，可手动重连`
  - 按钮：`重连`
- **用户动作**：等待自动重连；可手动重连。
- **保留数据**：全部（会话、场景上下文、恢复点）。
- **流转**：重连成功 → `idle`；重连失败到上限 → `failed`。

### 8. failed（失败）

- **触发条件**：不可恢复错误（协议损坏、server 崩溃、连续超时、审批通道不可用）。
- **用户可见文案**：
  - 主文案：`操作失败：<原因>`
  - 按钮：`重试` / `查看日志` / `重置会话`
- **用户动作**：重试、查看日志、重置会话（重置前二次确认）。
- **保留数据**：草稿输入；错误日志；会话内容按错误类型保留（认证/超时类保留，协议损坏类提示导出）。
- **流转**：重试成功 → `idle`；重置 → 新会话。

## 文案与交互规范

- 全中文；动作按钮 ≤ 6 字（`重试` `取消` `详情` `批准` `拒绝` `重连` `重置`）。
- 错误必须带错误码或可追踪的日志引用，不裸报"失败"。
- 不展示密钥、内部路径、凭据内容；诊断信息指向 README「启动/常见问题」与「常见模型错误排查」。
- 状态切换有可见变化（文案/按钮变化），不静默切换。
