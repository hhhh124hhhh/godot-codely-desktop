# Godot Codely 种子用户上手

当前面向愿意一起定位问题的 Godot / GDScript 用户，先用一个小项目完成一次可验证的修改。Godot Codely 基于 DeepSeek Harness；模型请求使用你自己的模型配置和额度。

## 下载与安装

从本仓库的 [GitHub Releases](https://github.com/hhhh124hhhh/godot-codely-desktop/releases) 下载，阅读该版本说明中的平台、已验证范围与已知问题。上游 DSH Desktop 安装包不包含这里的 Godot 能力。Actions 中名称包含 Dev 的包用于开发验收，不作为群内默认下载入口。

Windows x64 使用 `godot-codely-windows-x64-setup.exe`。当前早期包未签名，系统可能提示发布者未知；不要为安装而关闭系统防护，无法确认来源时先反馈。安装到普通应用目录，首次启动后应看到欢迎页或会话主页。

Linux 和 macOS 只有在对应版本说明列出原生验收及下载文件后才作为支持平台；CI 产物存在不等于已发布。Linux Office 功能不作为首批测试目标。

## 第一次任务

1. 备份测试项目，或使用独立 Git 分支。选择可以运行的 Godot 4 GDScript 小项目。
2. 在应用中配置自己的模型，先确认普通对话能得到回复。不要把 API key 发到群或 Issue。
3. 添加项目目录为工作区，选择 Godot Codely Lite 预设；如果预设不出现，记录版本并反馈，先不要手工补装随机插件。
4. 需要运行、校验或启动 Godot 时，为启动应用的环境设置 `GODOT_PATH`，指向本机 Godot 可执行文件，再重启应用。编辑文本本身不要求编辑器一直打开。
5. 先发送：“阅读这个项目，说明主场景和角色移动脚本的位置，暂不修改文件。”确认找对项目后，再做一个小修改，例如调整已有角色的跳跃速度，并要求校验 GDScript。
6. 检查文件差异，在 Godot 中运行验证结果。退出并重新打开应用，确认工作区和会话仍在。

首轮不以 C#、复杂多项目重构或任意玩法自动验收为成功标准。真实模型效果与配额取决于所用模型；自动化的固定回复测试不代表真实模型已经完成任务。

## 遇到问题

出现“插件导致启动失败”时，先保存页面中的技术详情：插件名、错误阶段和原始错误。兼容性只是可能原因，缺少依赖、文件损坏也可能出现同类提示。不要直接清空配置或删除会话。可用 `--safe-mode` 启动恢复界面；安全模式不提供完整 Godot 工作流。

Windows 正式版日志通常在 `%APPDATA%\godot-codely\logs`，用户数据在同目录下的 `harness`；Dev 包使用 `godot-codely-dev`。反馈前检查日志并删除 token、API key、私人项目路径及内容；不要提交完整配置或整个 Profile。

在本仓库 [新建 Issue](https://github.com/hhhh124hhhh/godot-codely-desktop/issues/new/choose)，包含：

- 应用版本、下载页面、系统版本及架构、Godot 版本。
- 操作步骤、预期结果、实际结果；从首次安装就失败还是升级后发生。
- 脱敏截图或错误原文；能复现的小项目可以单独提供。
- 是否阻断工作、重启后是否仍发生。
