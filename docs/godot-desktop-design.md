# Godot Codely 桌面工作台设计提案

跟踪 Issue：[设计与实现：Godot Codely 游戏开发桌面工作台 #20](https://github.com/hhhh124hhhh/godot-codely-desktop/issues/20)。Issue 包含整体方案及阶段清单；实现按批次提交 PR，实际接入与验证状态以第一阶段实现记录为准。

状态：整体设计方案 v1（2026-10-15），第一阶段开发中，实际接入范围见 [第一阶段实现记录](godot-desktop-phase-one.md)。原型位于 `website/desktop.html`；通过 `npm run website:preview` 预览 `/desktop.html`。原型中的项目、会话、文件差异及任务结果均为示例，不作为现有功能截图或验收证据。当前能力依据见 [能力探查记录](godot-desktop-capability-audit-2026-10-15.md)。本方案包含完整产品方向，实施阶段明确区分；当前原型不是每一项设计的完整实现。

## 产品方向

保留对标页面清晰的项目 / 会话层级、Agent 对话和底部输入框，把 Godot 项目的创作过程放到信息结构中心。游戏开发属性来自任务、上下文和验证，而不是装饰或虚构的内置引擎。品牌主色沿用 `build/brand-mark.svg` 的蓝色。

采用同一工作台下的两个视图：项目总览帮助开始任务；开发会话帮助推进、审查和验证任务。项目总览与会话共享当前项目，切换不应重建会话输入树。

## 布局与交互

| 区域 | 内容 | 设计目的 |
| --- | --- | --- |
| 左侧导航 | 项目总览、资源与技能规划入口、游戏项目及其会话 | 项目优先；不把每条对话当成孤立任务 |
| 项目栏 | 当前项目、分支 / 改动摘要、打开 Godot、运行项目 | 始终知道正在操作哪个项目；引擎操作有明确对象 |
| 项目总览 | 任务输入、理解项目 / 实现玩法 / 排查问题、继续会话 | 提示要完成的工作，而非展示大量未接通的仪表盘 |
| 会话主区 | 用户意图、Agent 解释、工具进展、文件改动入口、验证要求 | 保留完整上下文与审批流程；过程能追溯 |
| 右侧按需面板 | 项目上下文 / 改动 / 验证三个页签，可收起 | 压缩辅助信息，给对话与判断留出空间 |

默认浅色，另有深色设计预览。状态不能只依赖颜色。连接缺失、等待审批、执行中、执行失败、待运行验证与已验证必须用文字区分。没有真实结果时不显示“已连接”“运行成功”或诊断通过。

正式版优先考虑桌面 1280×800；窄窗口收起右栏，并保证可以再次打开。原型提供自适应布局，仅说明空间分配，不改变产品的平台支持范围。

## 与仓库的落地关系

根据 `docs/architecture.md` 与 `docs/patch-plugin-contract.md`，本设计不能演变成第二套业务前端或 Agent runtime。

| 设计能力 | 已有基础 | 正式实现仍需完成 |
| --- | --- | --- |
| 原生对话、会话与审批 | Harness Web UI，`packages/dsh-desktop-workbenches/client.js` 已有 `desktop.workbench.frame` 组合与 `conversation` 挂载 | 验证 Godot 工作台注册与激活契约；保持同一个会话树和输入状态 |
| 品牌与桌面 UI 定制 | `packages/dsh-desktop-client-ui/client.js` 的品牌 slots | 样式使用 `--dsw-alias-*`，中英文使用 locale，不注入 DOM 搬移上游组件 |
| 项目选择与会话关联 | 现有 workspaces、sessions 与工作台 service | 校验 `project.godot`，处理缺目录、无项目、切换中与失败状态 |
| Godot 启动、运行、导出 | `packages/dsh-godot-stack` 的 Godot 工具与 bridge | 明确宿主服务 / 工具调用路径、`GODOT_PATH` 缺失提示、进程生命周期、失败证据与打包可用性 |
| 文件与差异 | 现有文件预览；上游能力需按锁定版本再核验 | 不把原型差异当作可应用补丁；决定实际差异来源、基线与回退边界 |
| 项目状态与验证结果 | 当前 MCP / LSP 工具可作为数据来源 | 连接状态与执行结果接入；区分静态检查、引擎运行和用户验收 |
| 资源与技能 | 现有技能、MCP 与生图相关能力 | 当前只规划入口，服务可用性与用户凭据不能用示例状态代替 |

## 第一版范围

先做项目识别与总览、Godot 开发任务入口，以及复用原生会话的开发工作台；再接入明确的打开编辑器 / 运行操作与真实状态。文件差异审阅和验证面板按实际可用 API 接入。资源库、场景编辑、内嵌游戏运行与多 Agent 调度不在这一版设计承诺内。

实施前需补写各新增宿主能力的进程归属、契约、失败恢复和目标平台验收。客户端发现或启动链路发生变化时，按根目录 AGENTS 的真实子进程、HTML 引导、注册与 UI 激活要求验收；仅此静态原型不证明这些阶段已通过。

## 官网展示

当前官网的场景编辑器概念图不能当真实软件界面。桌面端方案落地后，用清理过隐私内容的真实截图或录屏替换。设计阶段若展示本原型，必须保留“设计原型 / 示例数据”标记，避免把规划能力当作已发布能力。

## 1. 用户目标与核心闭环

首批面向使用 Godot 4 / GDScript 的独立开发者和小团队，已有项目与自己的模型配置。不是从零实现游戏引擎，也不是让用户管理 Agent 基础设施。

核心体验是：**选择游戏项目 → 描述具体目标 → 检查执行与必要审批 → 审阅文件改动 → 运行验证 → 带着结果继续迭代**。成功标准是用户能确认改了什么、为何修改、执行到了哪一步、哪些结果已验证，以及失败后怎样继续。

第一版不承诺 C# 编译、内嵌 Godot 场景编辑器、游戏视图输入与截图自动断言、通用“一键撤销所有操作”、完整 3D / 音乐资产管线。资源与技能属于整体设计，后续按真实可用服务实施。

## 2. 信息架构与导航

```text
Godot Codely
├─ 项目入口：最近项目 / 导入项目
├─ 当前游戏项目
│  ├─ 项目总览
│  ├─ 开发会话列表
│  │  └─ 会话：原生对话 + 项目 / 改动 / 验证面板
│  └─ 资源与技能（后续阶段）
└─ 设置：模型与凭据 / Godot 路径 / 主题语言 / 原生设置
```

- 项目是持久的工作区；会话是该项目内一次开发协作。内部 task/run/requestId 不新建为竞争的项目身份。
- 项目总览显示项目名、目录、引擎配置摘要、最近会话和可执行的下一步。没有真实数据时展示空态，不填虚假场景、分支、连接状态和成功计数。
- 左侧项目与会话保持原生数据源。切换工作台不能吞掉通用会话，也不能把普通会话误绑为 Godot 会话。移除“最近项目”不删除项目文件；删除会话沿用原生明确语义。
- 当前工作台只控制主内容区；左侧完整重排属于后续宿主接缝工作，不能靠 customFrame 覆盖左侧或移动 React 管理的 DOM。
- 第一阶段先保留原生预设选择器，明确选择 Godot Codely Lite 并确认创建结果；具备显式 preset 契约后再提供“一步开始”。不悄悄改变用户全局默认预设，也不假定 sessions.create({ workspaceId }) 会自动选择 Lite。

## 3. 页面与操作规范

| 页面 / 区域 | 用户主要动作 | 内容与退出路径 |
| --- | --- | --- |
| 无项目 / 最近项目 | 导入 Godot 项目 | 原生目录选择；检查 project.godot；取消不创建半成品工作区。路径不可达时支持重新定位或移除记录，不删除磁盘文件 |
| 项目总览 | 描述开发目标并开始会话 | 理解项目、实现玩法、排查问题三种提示只填入输入框，用户发送后才执行；保留当前项目与模型信息 |
| 开发会话 | 协作、审批、补充反馈 | 原生消息、流式工具事件、取消、错误与恢复；输入草稿和会话滚动位置不因辅助面板切换而丢失 |
| 项目面板 | 查看与本轮任务相关的上下文 | project.godot 信息、当前场景、选中节点、未保存状态、来源时间；按当前项目匹配，无法关联时不展示上一个项目的数据 |
| 改动面板 | 逐文件检查本轮结果 | 文件路径、变更类型、差异基线、关联工具事件；二进制只说明类型和预览能力。没有完整基线时显示“无法生成完整差异”，保留原生工具记录 |
| 验证面板 | 运行检查并阅读证据 | 静态诊断、编译加载、冒烟运行与手动玩法检查分列；显示命令/工具、项目、时间、输出与失败阶段，不合并成含糊的成功灯 |
| 资源与技能（后续） | 查找已有能力或进入生成任务 | 仅显示实际存在的技能和服务；缺凭据、不可用、加载失败有对应提示。未实施前不在正式版放可点击的空壳入口 |
| 设置 | 配置模型、Godot 路径与常规偏好 | 复用原生设置、凭据与 locale；不再存一份密钥。Godot 路径修改后说明生效边界并验证可执行性 |

### Godot 操作的对象与语义

- **打开 Godot / Open in Godot**：调用现有 editor.launch 路径，打开独立编辑器。不画成应用内置场景编辑器。
- **运行项目 / Run Project**：运行磁盘上的项目，对应 project.run；运行后提供日志与停止入口。缺少 Godot、主场景或无法读取项目时先给出具体阻断。
- **在编辑器中运行 / Play in Editor**：只有当前项目编辑器活跃连接时才提供，对应 editor.play；与独立 project.run 分开标注。启动请求返回不等于实际进入 playing。
- **编译与冒烟检查 / Compile & Smoke Check**：对应 project.verify；说明只验证磁盘内容、GDScript / 场景加载和主场景短时运行。
- **停止运行 / Stop Run**：停止目标进程或当前项目编辑器运行，不杀掉其他项目或用户自行启动的 Godot。
- 超时后显示“结果未知，请先刷新状态”，不自动重放 Play / Run 等有副作用命令。与关闭会话、取消 Agent 和停止游戏分别处理。

## 4. 正常与失败流程

### 首次使用

1. 无项目：提示导入，允许跳过引擎配置先阅读和修改文本。
2. 选择目录：校验 project.godot，显示项目名与目录；不把普通目录直接假装成 Godot 项目。
3. 没有模型：输入草稿保留；提示前往原生模型设置，配置后回到原任务。
4. 没有 Godot：聊天、项目阅读和文本修改仍可用；运行类操作显示“配置 Godot 路径”。不把可选编辑器连接当全部功能的前置条件。
5. 使用 Lite 开始会话，确保实际预设与会话 cwd 正确；加载失败保留原始错误与重试入口。

### 一次玩法修改

1. 用户描述目标；Agent 先阅读项目并解释需要修改的文件。
2. 工具执行沿用原生审批。没有请求审批时不额外增加一层“确认发送”；有审批时清楚显示工具、目标和操作范围。
3. 修改结果进入工具记录和改动面板；新增/修改/删除分别呈现，不假设所有项目都有 Git。
4. 编译加载与冒烟分别显示结果；玩法效果仍需要运行或用户确认。
5. 用户可以继续反馈、查看失败输出或停止；不可因会话一句“完成了”将未验证项转为通过。

### 异常恢复

| 情况 | 界面应保留 | 可执行的恢复动作 |
| --- | --- | --- |
| 模型请求失败 | 草稿、历史消息、已发生的工具结果 | 修正配置 / 查看原因 / 按原生语义重试；不自动重复文件操作 |
| 等待审批 | 工具名、目标、请求归属、已执行步骤 | 允许一次 / 拒绝；面板不篡改审批的持久审计 |
| 用户取消 Agent | 已完成改动、日志和草稿 | 显示“已停止，已发生的修改仍保留”；不会把取消写成全部回滚 |
| 编辑器离线 | 最后快照及其时间，标记过期 | 打开 Godot / 刷新连接；仍可进行离线文本工作 |
| 有未保存场景 | 未保存的文件、当前任务与差异 | 提示在 Godot 中保存后再执行受阻操作；不代替用户自动保存或丢弃 |
| 运行 / 验证失败 | 原始输出、项目、阶段、时间与关联文件 | 查看日志 / 返回会话定位 / 修复后重新验证 |
| 工具超时或连接丢失 | 原请求标识及最后已知结果 | 先查询状态；结果不明时不标成功、不直接自动重放 |
| 项目切换 | 各自会话与草稿、任务结果、运行归属 | 新项目不继承旧项目状态；运行中的后台操作明确归属，切换不隐式取消 |

## 5. 状态模型与界面文案

状态采用相互独立的维度，不用一个“已连接”代替所有条件：

| 维度 | 状态 |
| --- | --- |
| 项目 | 未选择 / 检查中 / 就绪 / 非 Godot 项目 / 路径不可达 |
| 模型 | 未配置 / 可用 / 请求失败 |
| 引擎配置 | 未配置 / 检查中 / 可用 / 路径无效 |
| 编辑器连接 | 未连接 / 连接中 / 已连接当前项目 / 离线 / 状态未知 |
| Agent | 空闲 / 执行中 / 等待审批 / 正在停止 / 已停止 / 失败 / 本轮结束 |
| 验证 | 未执行 / 执行中 / 通过 / 失败 / 已过期 / 结果未知 |

“本轮结束”不等于“验证通过”。验证结果保留执行时间与所检查的内容基线；相关文件随后变化或无法确认基线时标为“已过期 / 需重新检查”。手动勾选用“已人工确认”，不转成“自动验证通过”。

## 6. 布局与视觉规范

- 桌面默认三栏：左侧项目/会话导航约 240–268px；中间会话为弹性主区；右侧上下文面板约 280–336px，可收起。工作台实现须遵守已有比例边界；要使用固定宽度和完整自定义主区布局时通过 customFrame，不给现有比例字段传非法值。
- 以 1280×800 为首版验收尺寸；中区变窄时先收起右栏，再允许用户收起左栏。主内容、消息滚动与底部输入框各有明确边界，不让输入框被长日志顶出窗口。
- 顶部工具栏显示当前项目与操作对象；主要动作随状态变化，同一上下文只强调一个主动作。停止与取消分开命名。
- 品牌强调色为 #2459d8，配冷灰背景、低饱和边框；正文使用深蓝灰。绿只表示有证据的通过，琥珀表示等待或未验证，红表示失败；状态同时显示文字/图标。
- 静态原型可使用色值；正式插件只通过 `--dsw-alias-*` 与现有主题能力实现，不另建产品主题系统。品牌 SVG 保持唯一源。
- 正文基准 14px，辅助文本 12px，页标题 20/28px；代码使用等宽字体，长路径可缩略但能查看完整值。主要点击区域至少 32px；触屏支持另行适配。
- 间距以 4/8px 为基础；同一角色控件统一样式，焦点、hover、disabled、busy 同批设计。浅/深色主题都验证，不用只适配浅色的固定阴影和文字色。
- 所有输入有标签；图标按钮有可访问名称；面板页签支持方向键；弹窗有焦点管理与 Esc 关闭；busy 状态避免误关闭；状态变化提供 aria-live，动画尊重 reduced motion。
- 左侧导航、窗口铬栏和应用菜单仍遵守宿主布局；尤其 macOS 折叠侧栏时使用现有 leading clearance，不覆盖系统窗口按钮。

## 7. 数据、进程与恢复边界

展示层复用既有状态源；正式接口的字段细节在实施时定义并验证，不把下列设计对象当成已有 API：

| 设计对象 | 最少需要的证据 / 归属 |
| --- | --- |
| 项目上下文 | workspaceId、可信规范化目录、project.godot 身份、引擎信息、更新时间 |
| 编辑器状态 | 当前项目、连接身份 / 活跃性、场景、选中节点、未保存标记、快照时间 |
| 本轮改动 | sessionId / task 关联、文件、操作类型、改动前基线或明确缺失原因、产生它的工具事件 |
| 操作结果 | 项目、请求标识、操作类型、pending / success / failed / unknown、阶段、输出与时间 |
| 验证结果 | 检查类型、被检查内容的基线、结果、原始输出、时间、是否过期 |

- Harness runtime 继续负责模型、工具、审批、会话与历史；插件负责项目工作台展示和任务上下文。
- Godot EditorPlugin 负责原生编辑器状态与 Play/Stop；宿主 main 或明确后端适配层负责特权调用、路径校验、进程管理；renderer 不直接跨端口绕过 Bridge Origin 限制。
- 新接口按当前真实工作区与会话归属鉴权；外部参数按 unknown 验证；状态订阅在项目切换、关闭、卸载与热重载时清理，旧异步结果不能写入新项目。
- 会话与草稿沿用原生持久化；项目文件由用户项目持有；验证 / 改动摘要以真实事件和可信基线派生。删除插件或退出工作台不删除用户项目、历史和凭据。
- 第一版仅提供审阅，不新增无可靠基线的全局回滚按钮。若后续支持撤销，必须逐文件检测冲突、说明可恢复范围并设计恢复路径；Editor Undo 和磁盘补丁恢复不能混称。

## 8. 实施拆分与完成判据

| 阶段 | 范围 | 完成判据 |
| --- | --- | --- |
| M1：项目入口与原生会话 | Godot 客户端入口、工作台注册、项目检查/总览、三种任务提示、Lite 明确选择、保留原生 sidebar/conversation | 临时 Profile 发现并激活；真实项目导入成功；普通目录拒绝或明确降级；会话 cwd/preset 正确；切换不丢草稿，不污染普通会话；缺包可诊断并可退回原生界面 |
| M2：引擎操作与真实状态 | Godot 路径、项目上下文、独立运行/日志/停止、编辑器连接/Play/Stop、编译冒烟 | Windows 临时项目真实执行；未保存/离线/无主场景/超时/失败分别有证据与出口；不误停其他进程；静态检查不冒充玩法通过 |

## 9. 统一验收与交付

- 正常流程：Windows 临时 Profile + Godot 小项目，从导入、模型/预设选择到“修改跳跃参数 → 查看改动 → 编译/冒烟 → 运行反馈”完成一轮；分别记录付费真实模型和固定模型适配器的验证范围。
- 状态流程：覆盖本方案状态矩阵，尤其无模型/无 Godot、审批拒绝、取消、离线、未保存、超时结果未知、外部文件变化和跨项目切换。
- 生命周期：重启恢复会话/草稿；反复切换和热重载不双挂载原生 conversation、不重复订阅、不串项目状态；停用工作台可返回原生界面。
- UI：中英文、深浅主题、1280×800 和窄窗口、长路径/长日志/流式输出、键盘/焦点和可访问名称；首版真实 Windows 验收，其他平台仅在实际验收后声明支持。
- 客户端加载/分发：新增 dsh.client、宿主 peer、预设和资源进入当前 dev/build/package；覆盖真实子进程、认证 HTML、bootstrap 注册、UI 挂载与安装资源闭包；Safe Mode 保持不加载该可选能力。
- 实现变更按根 AGENTS 运行相关行为回归、typecheck、build、完整测试和 diff 检查；各批次的实际执行结果见 [第一阶段实现记录](godot-desktop-phase-one.md)，本设计中的验收要求不代表已全部通过。
- 交付提供实际版本、环境、截图/录屏、执行结果、失败恢复与未验证项。旧版安装包、静态原型、HTTP 200 或历史测试通过均不能替代当前安装后的 UI 验收。

## 10. 原型覆盖与待细化项

当前原型已经覆盖正常项目总览、会话、项目/差异/验证切换、文件弹窗、手动清单、深浅主题与部分窄窗口交互。原型输入只在当前页面内保存，不表示持久草稿功能已实现。

本方案新增的首次导入、完整原生审批、引擎设置、真实日志、变更基线与生命周期由各实施阶段补齐；原型中的示例字段不能被拿来硬编码正式 UI。M1 首先核对本机锁定版本的实际 slots、session create/preset API 和仓库身份注册契约。存在缺口时补最小宿主契约并记录兼容性，不能静默退回错误预设或伪造成功。
