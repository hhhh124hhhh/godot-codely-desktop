# 联网检索方法论（godot-web-access）

> 本技能不是工具清单，而是一套**目标驱动的检索决策方法**。迁移自 Tuanjie Cowork web-access 的浏览哲学，适配本产品的通用搜索 / 网页抓取 / 平台搜索工具链。

## 核心原则：像人一样思考

执行检索任务时不依赖固有印象的步骤清单，而是带着目标进入：**边查边判断、遇阻就换道、不够就深入**，全程围绕「我要达成什么」做决策。

### ① 拿到请求 — 先定义成功标准

- 明确用户要什么：什么算完成了？需要拿到什么信息、得出什么结论、产出什么结果？
- 这是后续所有判断的锚点。先写清成功标准再动手，防止"查了很多但没有结论"。

### ② 选择起点 — 一个最可能直达的方式

- 根据任务性质、平台特征、达成条件，选最可能直达的第一步去验证。
- 通用知识 → 通用搜索；动态/登录页、社媒内容 → 平台搜索或专用通道；需要深挖 → 先搜索建立地图再精读。
- 一次成功最好；不成功进入 ③ 调整，**不在同一个方式上反复重试**。

### ③ 过程校验 — 每一步结果都是证据

- 每一步的返回不只是成功/失败的二元信号，而是对照①的成功标准评估推进的证据：
  - 路径在推进吗？结果的量级、质量、相关度是否指向目标可达？
  - 方向错了立即调整：搜索没命中 ≠ "还没找对方法"，也可能是"目标不存在"；
  - API 报错、页面缺预期元素、重试无改善 → 重新评估方向，不是加力重试。
- 一手信息优于二手信息：多次搜索无质的改进时，升级到更根本的获取方式（官网、官方仓库、原始页面精读）。

### ④ 完成判断 — 对照成功标准才停止

- 对照①定义的成功标准确认任务完成；不过度操作，不为了"完整"而浪费代价。
- 明确区分「已查证」与「一方称」：信息不足时如实标注，不把检索路径当结论。

## 工具分级

| 场景 | 首选 | 升级路径 |
|------|------|----------|
| 概念/知识/现状 | 通用搜索 | 命中摘要有价值 → 精读原文（web_fetch 全文） |
| 平台内容（抖音/B站/小红书等） | 平台搜索（video_search / image_search） | 定位账号/原帖 → 一手来源 |
| 需要引用的事实/数据 | 通用搜索（多关键词并行 ≤3） | 官方文档/仓库精读，保留来源 URL |
| 判断信息真伪 | 定位一手来源比对 | 交叉验证 ≥2 独立来源 |

## 反模式（禁止）

1. **同方式重复重试**：同一关键词/同一入口连续失败 2 次 → 换关键词/换通道/换策略
2. **路径当结论**：查到了资料 ≠ 完成了任务；必须得出用户要的结论或产出
3. **无锚检索**：没定义成功标准就开始搜，最后以"信息很多"收场
4. **来源混淆**：引用时必须区分工具返回的一手/二手来源，按来源规则附引用
